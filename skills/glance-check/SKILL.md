# 一眼看懂检查（glance-check）

**前提（用户原话）**：和老师讨论、展示 PPT 和图表时，老师要能一眼看明白。
不追求命名完美，追求读者不用查定义。

专家依据和来源见 `<你的论文仓库>/notes/图表PPT一眼看懂_专家规则_20261110.md`。

## 输入
用户指定的 PPT（.pptx）、图（.png/.pdf）、表（LaTeX/Markdown）或一份论文稿。没指定就问要查哪个。

## 步骤

### 1. 列出所有名字（先列，不改）
把每个出现在页标题、图例、坐标轴、表头、行名、图上标注里的名字抽出来，记下出现位置和次数。
- 同一概念的不同叫法要合并成一行（例：`one-line` / `first-order` / `zero-solve` 指同一样东西）。

### 2. 逐个按四条命名规则打分
| 规则 | 不合格的信号 | 依据 |
|---|---|---|
| ① 默认不造缩写，用描述性短语 | 自造缩写、内部代号（P168、臂名、实验编号） | Mensh & Kording 2017；Nature 作图指南 |
| ② 一个概念全稿一个名字 | 同一东西在 PPT / 图 / 表 / 正文叫法不同 | Ehrhart & Evelo 2021；Google 技术写作 |
| ③ 短名必须明显比全称短、且反复出现（≥3 次） | 只出现一两次的短名；短名没比全称短多少 | PLOS CB 规定；Google 技术写作 |
| ④ 借用通用词不能装别的意思 | 领域里该词有另一常见含义，可能误读 | Lipton & Steinhardt 2018 |
| ⑤ 不怪：领域专家一眼知道指什么 | 生造的比喻词、口语词、本组才懂的说法（如 "one-line"、"repair"、"stacked"） | 用户要求 |

**规则⑤怎么查（不靠感觉）**：
- 优先用本领域现成术语（如 EIT 里的 linearized / Jacobian / FEM forward solves / training prior）。
- 每个建议的名字，到本领域论文里搜一下（标题、摘要、图例），**至少 3 篇同领域论文用过同一说法、同一意思**才算"不怪"；搜不到就换成搜得到的说法，或改成描述性短语。
- 建议表里写明找到的论文例子，方便用户核对。

另外按位置查长度：
- 图例、表头、行名：1–3 个词。
- 页标题、图标题：一句结论。
- 图注或正文首次出现：全称 +（短名）。

### 3. 查版面（结论是否一眼可见）
- **PPT 页标题是一句结论句**，不是主题词（Alley：assertion-evidence）。
- **PPT 以图表为重，少条目**（用户要求；Alley：用视觉证据代替条目列表）：
  - 每页 = 一句结论标题 + 一张图或表作证据；正文文字最多 1–2 行短句，不用条目列表。
  - 能用图表表达的观点就不用文字讲：条目 ≥3 条的页面要标出，并建议换成哪种图 / 表（对比 → 柱状或点图；流程 → 示意图；数字 → 小表）。
  - 解释性的话放到讲稿备注，不放在页面上。
- **最醒目的就是结论**：结论那条线 / 那一行上色或加粗，其余变灰；退后眯眼看，第一眼是不是结论（Bang Wong：salience = relevance）。
- **线少直接标名，线多才用图例**。
- **表**（Schwabish / Ehrenberg）：表头与表体分开；数字右对齐、文字左对齐；1–2 位有效小数；单位只写在表头；关键值突出；可加一句话总结。

### 4. 输出（小步，一次一张表）
先只给一张表，等用户确认再改文件：

| 现在的名字 | 出现位置 | 问题（规则号） | 建议改成 | 有无争议 |
|---|---|---|---|---|

- 明确该改的直接给建议；拿不准的（会影响论文卖点的核心名字）标"有争议"，让用户定。
- 版面问题另列一张短表，不和命名混在一起。

### 5. 改完后做"外人测试"
根因是"知识的诅咒"（Pinker）：作者看不出自己的内部叫法别人不懂。
- 用一个不带本次对话上下文的子代理，设定为"本领域专家（如做 EIT 的老师）、没读过我们的稿子"，只给它图 / 表 / 页面截图，让它说出"这张图的结论是什么、每个名字指什么、哪个名字看着怪"。
- 它说错或说不出的名字，回到第 2 步再改。
- 最终仍以用户拿给老师看的反馈为准。

## 注意
- 只改名字和版面，不改数据和结论。
- 核心贡献的短名最多留 1–2 个，其他一律描述性短语。
- 图内文字一律英文（用户偏好），字体 Nimbus Sans。
