# 顶会论文全流程

完整手册（中文、过关标准、范例文件、教训）在
`<你的笔记目录>/科研方法/顶会论文全流程_工作手册.md`。**先读它。**
范例目录：`<你的笔记目录>/反问题顶会调研/扩散流反问题/`（文件 00–21 按时间排开）。

参数是研究方向，或者当前所处的阶段（例如"阶段 4，复核 xx 论文"）。没给就问。
如果方向已经有进度，先读该方向的编号文件和项目记忆，判断现在在哪个阶段，从那里接着走，不要从头来。

## 九个阶段（每个阶段有过关标准，不过不往下走）

1. **选题**：调用 `/research-idea-loop`。先写下用户的独有资产（数据、算力、领域知识、现成代码）。生死实验按事先写死的标准判定。
2. **放大意外**：
   - 推广到 ≥4 个、跨家族的方法和 ≥2 个任务；
   - 主动找反例，按反例改叙事，不藏；
   - 做一个有闭式解的玩具理论，给出可证伪的预测，用已有数据验证；
   - 修复方案用盲测检验；
   - 维护"撤回的说法"清单。
3. **真实数据**：尽早上。拿不到或讲不清就换数据。判定标准先预注册，PARTIAL 如实写并解释原因。数据协议由用户本人确认；数据只留本机。
4. **复核排雷**：
   - 小样本结论用大样本复核；
   - 统一预处理口径；
   - 审计基准代码 bug；
   - 看真实样本；
   - 参考文献逐条核实，原文引语对到字。
   - 抓到的陷阱可以写成论文贡献。
5. **写初稿**：提纲 → 分批写（摘要、引言、方法先给用户看风格）→ 数字放在 `numbers.tex` 单一来源 → `\todo` 清零 → 页数合规、0 溢出、0 未定义引用。大改前备份；复制软链接目录用 `cp -r dir/. target/`。
6. **包装**：
   - 用 `/sentence-mimic` 学同领域高产作者，套路手册在范例的 `包装学习/`；
   - 标题不能和自己的结果冲突；
   - 正文 3–4 张不同类型的图（钩子图、定性图、概念图、机理图）；
   - 配色用 dataviz 校验，模仿图风格用 `/figmirror`；
   - 最后过 `/glance-check`。
7. **内审**：
   - 提前回答导师必问的问题：为什么重要（动机和具体后果）、读者怎么用（一条可执行的规则）、关键常数从哪来、内部术语换成通用说法、外行能不能看懂。
   - 扮审稿人给出 3 条拒稿理由和对应的反驳。
   - 稿件和幻灯片里的每个数字，对原始记录逐条复核。
8. **外发和组会**：只准备邮件草稿和附件，**用户明确同意才发，绝不代发**。组会反馈逐条写进待办，每条标"改稿 / 加实验 / 只需解释"。
9. **投稿前**：
   - 每 2–4 周做一次撞车监控，新出现的近似工作要在稿子里点名区分；
   - 看最近会议的趋势，主投和备投各准备一套讲法；
   - 官方模板发布后换模板、复核页数、匿名化。

## 规矩

- **每个实验不超过 5 分钟（墙钟时间，从启动到出结果）。**
  - 启动前先估时间：先跑一小份（比如 1/10 样本）计时，再外推。
  - 估计超过 5 分钟就先缩小：少样本、少视图、换小模型、少扫几个点。
  - 或者拆成多个各自不超过 5 分钟的小实验，可以并行跑。
  - 不能一次跑超过 5 分钟的长实验。确实需要的话，先说明原因和预计时长，等用户同意。
- **每工作满 1 小时，更新一次进度幻灯片。**
  - 项目目录里维护一个 `进度汇报.pptx`，用 pptx skill 制作。
  - 每次更新追加或修改页面，写清这一小时的新结论、关键数字表或图、撤回的说法、下一步。
  - 封面写最后更新时间。
  - 更新完告诉用户文件路径和这次改了哪几页。
- 每个阶段的产出写成编号文件（接着项目里已有的编号往下排）。
- 判定标准先写进文件再看结果。
- 说错了立刻写"更正"并告诉用户。
- 理论、实验、红队、文献能并行就并行，用后台子代理和 sbatch 数组（见 madar 和 ku-h100 的记忆）。
- 子代理查来的关键文献，自己抽查至少 3 条。
- 不绕过人机验证和反爬。
- 汇报说人话：先结论（好消息还是坏消息），再表格，最后给推荐。
- 每个阶段结束时更新项目记忆：阶段、关键数字、撤回的说法、投稿计划。
