# 自主科研循环（单次迭代）

借鉴 orchestra-research autoresearch 的双层循环与 krasserm 的分级晋级。

**尽量别停**：需要用户决定的事，默认写进 `pending_approvals`（简报"需要你决定"会列出），然后继续做别的假设。只有三类事把 status 改为 needs_approval 停机：改变研究目标/转向、超预算、不可逆的对外操作（公开仓库、许可证）。

## 0. 读入（必做，不依赖聊天记录）
1. `goal.yaml`（目标、成功标准、预算、边界）
2. `research-state.yaml`（status、iteration、best、hypotheses、next_action）
3. `findings.md` 的"已否定"——新假设不得重复已否定方向，除非写明新理由
4. 最近 `git log --oneline -10`

若 status ≠ running：什么都不做，直接结束。

## 1. 决定本轮做什么
- iteration 是 5 的倍数，或连续 3 个假设无增益 → **外层决策**（见第 6 节），不跑新实验。
- 否则按 `next_action` 做；没有则提一个新假设：
  - 主线（约 80%）：沿当前最好方向的可证伪改进。
  - 自由探索（约 20%）：允许大胆的新结构/新方法，但同样预注册、同样判定。
  - 统计 hypotheses 中两类比例，按 `budget.explore_ratio` 平衡。
- 选假设的原则：
  - 由已观察到的问题或现象引出；找现有方法解决不了的缺口和失败案例，有人做过不要紧，可以拆掉别人默认成立的假设。
  - 同等效果下选更简单、更符合直觉的方案；快但不能糙。
  - 不穷举参数和组合，挑最可能、最值得的少数假设。
  - 先复现已知基准数字、查清原有设置（训练阶段、amp、启动命令），再往下做。
- 调研限时：实验阶段每小时调研 ≤5 分钟、聚焦本领域；专门的调研阶段另设预算。
- 先用 ≤5 分钟的实验验证想法，不写长篇分析。

## 2. 预注册
- 复制 `hypotheses/_模板/` 为 `hypotheses/H<编号>_<中文短名>/`，填 `protocol.md`。
- 判定标准写死数字（参照 `success_criteria`）。判定分档只写"支持/否定/存疑"对应的数字条件，不预写机制解释（如"存疑就说明增益来自 X"）；机制要靠单独的消融来证明。
- **小效应要够种子**：预期差值小于 2 倍种子间标准差时，预注册 ≥5 个评估种子；或写好"存疑就在新种子上复验"的规则（新种子与原种子不重叠）。3 个种子里 1 个就能翻转结论时，不得把结果当定论写进 next_action（11-22 长跑巡检）。
- **goal 里的参照按 goal 的口径复现**：goal 写"同训练时间预算"就按同墙钟跑、参照也要调参；口径不同只能当描述性对照，result.md 写明"same epochs, not same time; untuned"。
- **先 `git commit` protocol.md，再跑实验**。

## 3. 跑实验（分级）
| 阶段 | 上限 | 规则 |
|---|---|---|
| toy | `budget.toy_minutes`（默认 5 分钟） | 用 `timeout` 包住命令；小数据/少步数；先看信号 |
| pilot | `budget.pilot_minutes` | 仅当 toy 有信号；≥3 种子、配对比较 |
| full | `budget.full_hours` | **不得自行启动**：写进 `pending_approvals`（理由 + 证据），继续做别的；用户创建 `approvals/H编号.ok` 后才能跑 |

- **所有实验一律用** `python 实验.py --stage toy|pilot|full --h H编号 -- <命令>` 运行：它检查预注册已提交、按阶段限时、Full 需人工批准、累计算力不超预算，并写 `logs/实验记录.jsonl`。直接 `python hypotheses/...` 会被守卫拦截。
- 被守卫或 实验.py 拒绝时：照提示做，不要换写法绕过。
- Bash 命令里不要用 `for`/`while` 循环和变量赋值（如 `D=...`），权限系统无法匹配，会被拒；多个种子就分成几条命令依次运行。
- `python 实验.py --用量` 查看已用算力。
- **只剩等批准时就停机**：如果本轮唯一能做的事是等人批准（没有别的值得做的假设），把 status 设为 needs_approval、写清在等什么后结束，不要每轮只确认"仍无批准"（11-22 巡检：连续空转）。人放批准文件后 harness 会自动恢复。
- 本机 GPU 由 实验.py 自动挑空闲卡（允许的卡都忙会先等）；`logs/实验记录.jsonl` 里 `contended: true` 的运行是在卡被别的任务占着时跑的，计时、吞吐类结果不能用，判定时排除并重跑；不要为此停机申请。实验.py 还会在运行中监测同卡进程数：超过 `max_run_seconds` 但同卡有别的进程时记为 `rerun_needed`（不算作废、也不算有效），卡空闲时重跑同一配置。**计时类实验不要并行启动**（11-22：并行启动的运行互相拖慢，被杀或超限，选参网格被随机截掉）。
- **算力自动选**：实验.py 默认 `--where 自动`，比较本机 4090、ku-h100（H100）、madar（H200）谁先跑完（排队 + 同步开销 + 预计用时 / 速度），自动选最快的并打印估算表。较长的实验请给 `--预计分钟 N`（本机 4090 上的预计用时，写在 protocol.md 的预计耗时里），估得准选得才准；只有确有理由时才手动指定 `--where`。选中集群时提交后立即返回（madar 账号固定 <slurm-account>）。同一假设的对照组要在同一种卡上跑，计时类比较不跨卡。提交后可继续做别的（如另一个 toy）；没事可做就把 `waiting_for_jobs` 设为 true 并结束本轮，harness 会在作业结束、结果同步回来后再唤醒你。
- 被唤醒时先看 `logs/作业.jsonl` 和 `logs/slurm/` 判断作业是否成功。
- 代码放 `hypotheses/H*/` 或 `src/`；结果存 JSON；固定种子。
- toy 预计超过 5 分钟就先拆小；更长的实验必须先有 toy 信号。
- 跑之前在 protocol.md 写预计耗时（含排队）；长任务按预估时间回来查，不持续盯。运行时间明显超过预估要查原因，不接受。
- **样本拼图由 harness 自动画**：训练脚本在验证集上预测后保存 `预测_验证_<标签>.npz`（`pred` 预测类别；可再存 `prob` 各类概率，用来挑错得最自信的样本），实验.py 跑完会自动生成 `样本拼图_<标签>.png`。你只需用 Read 看这张图、在 result.md 写看到的规律；不要自己写画图代码。
- 权重只存最优、被判"支持"的检查点；代码和复现说明照常入库，依赖的小文件即使被忽略也 `git add -f`。
- 数据量放大的检查：网络容量和训练步数跟着放大，每档训练到验证集进入平台。
- 报错：修 bug 可以；**不许换方法/模型/数据集来绕过**，绕不过就判"存疑"并记录原因。

## 4. 判定
- 只按 protocol.md 的标准判：支持 / 否定 / 存疑。默认判据：配对 bootstrap 95% 置信区间不跨 0，且 ≥3 个有真随机性的种子方向一致。
- **参数改动要先修正预注册**：toy 定出的参数用到 pilot 后要改（如 epoch 数），先新建同目录的 `protocol_修正.md` 写明改了什么、为什么、在看到哪些结果之前，并提交，再重跑（已提交的 protocol.md 被守卫锁定，不能改）；不得在看过测试结果后直接改。
- **结果文件不覆盖**：文件名带阶段、种子和版本（如 `结果_pilot_s0_e70.json`），旧结果保留。
- **单种子、计划外的观察只算线索**：写进 result.md 的"意外现象"并标"线索（未验证）"，不进 findings 的结论栏，不能作为 next_action 的依据，也不能写进论文或 PPT。
- **调参对称**：网格对各方相同；选中值落在网格边缘时，向该边缘外侧扩展（上下两侧都适用），各方同样处理。
- **分析口径冲突时取保守**：同一比较有两种合理口径（如两种调参方式）结论相反，结论按较保守的写，并同时报告两者。
- **bootstrap 的重采样单位**：配对 bootstrap 以评估样本为单位重采样：多个种子共用同一个评估集时，先对每个样本取各种子差值的平均（得到 N 个数），再对这 N 个样本重采样；**不要把种子×样本拼接成 3N 个数重采样**——同一样本被重复计入，CI 会窄约 √种子数 倍（11-22 巡检发现）。各种子评估集不同时，按种子分层重采样；只有种子数 ≥5 时才可对种子重采样。3 个种子时对种子做 bootstrap，CI 就是差值的最小到最大，不能作为判据。
- **选参种子不进最终统计**：用于选参的种子不计入最终均值与 CI，最终评估用另外的种子。
- **判定门槛统一**：所有假设的"支持"沿用 goal 的统一判据（配对 CI 不跨 0 且 ≥3 种子方向一致）；"可用/值得"阈值另列，用来决定是否值得继续，不得当作否定线。
- **存疑不等于否定**：判"存疑"的方向不得写成"不再投入"；要放弃须有"否定"判定或写明成本理由。
- **"否定"只有两种**：CI 整个落在不利一侧；或 CI 整个落在预注册写死的等效区间 ±δ 内（"否定（等效）"）。"CI 跨 0 且均值差 ≥0"之类不显著结果一律判存疑，不得写进 protocol 的否定档（11-22 巡检，审查标为高）。
- **什么算"同一份数据"**：同一样本池换折、重复 k 折、交叉拟合、换子采样种子，都仍是同一份数据；"新划分"指从未参与本问题任何选参或判定的样本。存疑后的复验必须用新划分。
- **goal 里的硬约束**（如单次训练时长）不得自行突破；超限的结果作废，不能当结论或写进论文/PPT；要放宽就写进 pending_approvals。
- 认为判据有缺陷时：仍按原判据判定，在 result.md 写理由和修正方案，把"判据修正"加进 `pending_approvals`；要验证修正后的判据，就新开一个复验假设。不停机。
- 小差别必须看种子间方差；单种子提升只能算"有信号"，不能算"支持"。
- **训练时间对等**：有时间预算的课题，新方法和基线的实际训练时间相差不超过 5%；否则先把基线也用满预算再比。
- **基线同等调参**：基线必须和新方法用同样的选参预算（同一验证集、相当的搜索组数或训练步数）；用默认参数的基线不算"最强合理基线"。
- **种子要真有随机性**：模型是确定性的（如 SVM、lbfgs 逻辑回归）时，种子必须作用在数据划分或数据子采样上；种子间方差为 0 的"多种子"不算满足种子数要求。
- **测试集只用于最终报告**：选参、挑基线、比较协议一律用验证集；测试指标只能通过 eval 的 score()/correct_mask() 获取（每次调用都被记录），且每个假设都要有人创建的 `approvals/测试集_H编号.ok` 才能用；没有就写进 pending_approvals，继续做别的。训练脚本里不要顺手算测试准确率。同一主张在测试集上只判一次，之后换协议、换种子、换网格的再比较都只能在验证集上做，或用新划分。
- **存疑后的复验必须换数据**：判"存疑"后，在同一份数据（同一测试集或同一验证划分）上加种子、换协议重判一律不算"支持"；复验要用新的数据划分，或在原预注册里事先写明"存疑则加到 N 个种子"。论文与 PPT 不得把这类重判称为 replication。
- **报告数字与选参数据分开**：选参用的验证集上的数字只能标注为"选参用"，结论数字来自测试集的一次性使用（score()）或另留的未用于选参的划分。
- **不许换检验救结论**：某个主张被判"存疑/否定"后，不得在同一测试集上换统计检验、换指标或换门槛来重新判"支持"。想继续，只能用新证据：新的数据划分或另留的复验集（只加新种子不算新证据，见上一条），并在新 protocol.md 里写明"复验 H编号"。
- 同一主张在同一测试集上只能判定一次；之后的再分析只能写进"意外现象"，不能当结论。
- 加噪声、扰动或小样本时，必须有同幅度随机对照或有限样本对照。
- 异常大或异常小的数字（如指标恰好为 0）先拆开查清原因，不凭猜。
- 提升或变差都要归因到具体环节，不笼统说"有效"。
- 有公认外部测试集或外部标尺（如挑战赛官方分数）时，结果要和它对照。
- 填 `result.md`：预期 vs 实际、数字（均值 ± 标准差、置信区间、种子数）、归因、证据路径。

## 5. 记录并提交
0. `pending_approvals` 中已由人落实到 SKILL.md / CLAUDE.md 的条目删掉，避免简报反复列出。
1. `findings.md` 追加一行（日期 · H 编号 · 结论 · 关键数字 · 证据路径）。旧条目需要降级或纠正时，不改旧行，追加一行"更正 H编号：新的措辞 · 依据"；同时在该假设的 result.md 末尾追加"## 更正（日期）：新判定 · 依据"，并改 research-state.yaml 的 verdict，三处保持一致（11-22 巡检：只改了 findings，result.md 仍写旧判定）；论文、PPT、next_action 以最新更正为准。"存疑 / 待复验"里的条目解决后（复验完成、阻塞解除），同样追加一行"已解决 H编号：结果 · 证据"，别让旧的待办一直挂着。
2. 更新 `research-state.yaml`：iteration+1，hypotheses 条目，best（仅当按标准"支持"），next_action。
3. `git add` 本轮文件，`git commit -m "H编号 结论：一句话"`（只提交自己改的路径，不 push）。
4. 论文或图表用到的汇总文件：生成前确认它晚于依赖的原始结果；过期的改名加 `_STALE_日期` 保留，不删。

- **基线调参不吃掉预算**：基线调参已用掉墙钟或 GPU 预算的 30% 以上时，本轮立即做外层决策（不等第 5 轮），在 next_action 写清剩余预算还能跑几个方法假设；剩余墙钟不足 30 分钟而主目标假设一个都没开始时，写进 pending_approvals 请人决定是否追加预算（11-22 长跑巡检：4 轮全花在基线上，方法一个没做）。

## 6. 外层决策（每 5 次迭代）
读全部 result.md 与 findings.md，选一个并写进 next_action：
- **深挖**：最好方向还有明显可改进处 → 下一个主线假设
- **拓宽**：主线停滞 → 下一轮提高探索比例
- **转向**：现方向证据不足以达到目标 → status=needs_approval，写清理由与证据（三类停机事项之一）
- **晋级**：pilot 已按标准支持 → 写进 `pending_approvals` 请求批准 Full，继续做其他假设
- **放弃**：方向不成立就干脆放弃；该方向下载的大模型/大文件列出待删清单（路径、大小、全库引用检查结果）写进 `pending_approvals`，不自己删
- **结束**：达到成功标准或预算将尽 → status=done
决策理由写进 `findings.md`（一行）。每日简报与每周交接由 harness 另行调用 daily-brief / research-handoff 生成，这里不用写。

## 禁止
- 修改 goal.yaml、eval/、测试集划分、基线结果
- 事后改判定标准、挑种子、只报有利结果
- 结论没过门槛后，在同一测试集上换检验/指标/门槛重新判定
- 编造数字、引用、理论解释
