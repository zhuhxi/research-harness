# Vibe知识大赏 短片流程（石头剪刀布那一期的实际做法）

样板工程：`~/Desktop/选题学习/rps_remotion/`（git 里有 v1→v6 的每一版，可直接复制当模板）。
流程依据：`~/Desktop/选题学习/素材参考/Vibe知识大赏/流程_定稿_v2.md`（11 步，来自 HeyChengC / LeaderAI 等逆向爆款的开源 skill + 16 条爆款拆解）。

## 用户的硬要求（不要违背）
- **无配音，有字幕**：字幕就是旁白，底部单行，每句 ≤16 字、句末无标点。
- **配乐用赛道常用曲**《Claude Opus 5.5の小曲》：`~/Desktop/选题学习/素材库/配乐/Vibe常用曲_待核实/Claude小曲_BV1ySaf69EAp.m4a`。别自己挑曲子（用户原话：「模仿别人怎么做的 改进就好 别拍脑袋做」）。
- **知识要有用、有逻辑、层层递进**：观众想要「什么时候该怎么做」的规则，不要零散冷知识（用户原话：「大家就是想知道有用的规则」）。
- 1 分钟左右；每个改动先说爆款怎么做的，再动手；做完一段先给用户看/听，别让用户久等。
- **黑色调背景**：每期都用暗底（#0A0A1E 一类），题材像菜单/答题卡也在暗底上做，不换纸面浅色（2026-11-10 用户定）。
- **竖屏为主**：画面按 1080×1920（9:16）设计，字幕、大字、主体都排在竖屏安全区；横屏版只是附带。
- **画风圆润没棱角、亲和，但不要太可爱（不要 kawaii 大眼腮红）、也别太冷酷**；画面要有真实场景（进店、街道、柜台）。
- **不用「章节卡中央砸出再缩到左上角」的收缩动画**（用户觉得不漂亮），规则切换先找爆款竖屏参考帧再定新做法。
- 下载只下到 KU 服务器，不下到用户 Mac；不绕验证码；不用真人肖像、不克隆声音；不 push git。

## 步骤

### 1. 选题 + 事实表
- 套「算法之外_」公式：人人碰过的小问题 + 自己数/算出来的反直觉数字；标题「问题？｜反常识数字」。规律见 `素材参考/Vibe知识大赏/选题规律.md`；选题池来自云端每小时调研 routine（trig_01QbEnMwAfbtMiUqzftPheKb）。
- 调研放 `选题调研/<题目>/调研_v1.md`；能自己跑模拟就跑（如 `模拟_v1.py`，100 万局），片里写「我自己模拟的」。
- 事实表写进工程的 `film.md`：每个屏上说法 → 出处（作者、年份、期刊、表号）→ 把握程度。数字必须对得上原文（石头剪刀布踩过：42% 是「盯住对手习惯」的上限，不是口诀的胜率）。

### 2. 故事骨架：3 条递进规则
- 一条主线串起来，后一条建立在前一条之上。石头剪刀布：没信息（第一把出布）→ 有信息（看上一把输赢）→ 信息被反利用（高手 → 你也乱出）→ 彩蛋（机器人偷看）→ 收束「赢靠的都是信息」。
- 开头抛一个网上流传的说法（「口诀胜率 80%」），中途必须正面回应它（红叉打掉），别留悬念不收。
- 结尾回到开头的画面 + 一句互动（「你第一把出的什么 布扣 1」）。

### 3. 找形象（最花时间）
- 一个贯穿全片的形象（石头剪刀布：擂台上两只发光线描的手）+ 每条规则一个具体可动的物件（净胜条、秒表、量表、机器人）。不用抽象点线圈代替。
- 每个画面动手前先找一张爆款参考帧对照。

### 4. 字幕稿 + 时间轴（`src/script.ts`）
- `LINES` 一句一行，`t`/`d`/`text`/`color`（关键词上色：GOLD 有利、RED 不利、CYAN 机器/技术）。
- 配乐 112.9 BPM，小节 2.126 秒；曲子 17.01 秒是第一次起势。从曲子 `MUSIC_OFFSET=11.81` 起播，让起势落在片名卡 5.2 秒。时间网格 `B(k)=5.2+2.126k`，每句一小节，每 4 小节一个乐句 = 换一个段落/规则。
- 结构：冷开场 0–5.2s（0.3 秒出第一句，抛问题 + 金句数字）→ 片名卡 B0–B2 → 规则一/二/三（章节过渡别用缩到角落的动画）→ 彩蛋 → 结尾，共 60 秒。

### 5. 画面（Remotion，`src/kit.tsx` + `src/Film.tsx`）
- 暗底 `#0A0A1E`、发光线描（`Defs` 里的 glow 滤镜）、Noto Sans/Serif CJK、每帧 1 个主角 + 1 处大字 + ≤2 处小字。
- 复用 kit：`span/win/ease/mix/rnd` 时间工具、`Subtitles`、`Cite`（出处小字）、`Big`、`Ambience`。
- 场景之间让元素长出来/推拉过去，不硬切；字幕出现后 0.3 秒内屏上要有动作，静止不超过 2 秒。
- 环境：`export PATH=~/miniconda3/envs/node20/bin:$PATH`。
- 快速看帧：`./stills.sh 3 10 25 ...` → `out/stills/sheet.jpg` 联系表；或半尺寸渲染草稿再用 ffmpeg 抽帧（逐帧 still 太慢）。

### 6. 声音（`audio_mix.py`）
- 音效库 `素材库/音效/自制/`（16 个 wav：咚_重音、闪_金光、嗖_滑入、叮_出现、啪_盖章、嗡_错误、嘀_计数……）。只挂在大事件上（片名卡、章节卡、数字砸下、揭晓），挂点写成 `cue(B(k)+偏移, 名字, dB)`。
- 配乐 ×0.85 + 音效，进 0.6s 出 2.5s；输出 `public/audio/mix.wav` 和 `sfx_only.wav`（只音效版，备平台版权识别时替换）。
- 成片响度：ffmpeg `loudnorm=I=-14:TP=-1.5`。

### 7. 渲染
```
npx remotion render src/index.ts Film out/<名字>_vN.mp4 --gl=angle-egl --chrome-mode=chrome-for-testing --concurrency=12
```
1080×1920（竖屏）为主、30fps，需要时再出横屏；再做一版只音效版。每版 git commit（`Film_vN.tsx.bak` 留大改前的快照）。

### 8. 独立审片（最多 3 轮）
- 派一个没参与制作的 subagent，只给成片抽帧联系表 + 字幕稿 + 事实表，按 9 维打分（故事清晰、开头、丰富度、设计秩序、变化频率、运动质感、转场、完成度、音画同步）+「离爆款多远」。
- 修最差的 3 项。石头剪刀布审出来的典型问题：计时器数字错、图标表示的对象搞反、数字归属错、逻辑跳步（「高手」凭什么）、开头抛的说法没收、标签重叠。转场一直是最低分项，优先改。

### 9. 封面 + 文案
- `src/Cover.tsx`，Root 里出 CoverH 1920×1080、CoverH43 1440×1080、CoverV 1080×1440 三张到 `out/发布/`。封面 = 片名卡问题 + 一个反常识钩子 + 底部数据来源小字。
- `发布文案.md`：三平台标题和正文。
  - B 站：「Vibe知识大赏｜问题？数据里的 N 条规则」，分区知识，10 个标签含活动话题「vibe知识上新啦」，简介写规则摘要 + 参考文献 + 「配乐：《Claude Opus 5.5の小曲》」，置顶评论互动问题。
  - 抖音：标题 ≤30 字，描述带 #vibe知识大赏 等 5 个话题，加入官方活动「Vibe知识大赏」。
  - 小红书：标题 ≤20 字，正文 emoji + ①②③ + 5 个话题。
- 只用成片里兑现了的钩子。

### 10. 三平台发布
- 方法见 `素材库/发布/三平台上传方法.md`：视频切 9 MB 块 → 注入隐藏 input 逐块 file_upload → 页面里 `new File(chunks)` 拼回 → DataTransfer 塞进平台 input + change 事件。
- 各平台坑：B 站自动选的分区（vlog）和标签要改掉、简介用 Quill `setText`；小红书会把封面按视频比例裁成 4:3，传 4:3 封面；三平台都勾 AI 生成声明。
- 发布/定时前要用户明确说发。定时：B 站和小红书填北京时间，用户在迪拜（迪拜 12:00 = 北京 16:00）。改定时为立即发布时，B 站编辑页简介可能是空的，要重新填。
- 发完提醒：配乐版权未核实（被识别就换只音效版）；上线第一小时回评论，回复两三句话。
